Launch and manage a Monte Carlo yield campaign directly, rather than requiring
a pre-run `klt sim` report -- issue #906, Phase 2a of the statistical/yield
epic #710. A campaign spec is a `klt sim` request document with a mandatory
`monte_carlo` block; seeds are derived deterministically when omitted so the
same spec re-run reproduces the same sample set, dispatch reuses `klt sim`'s
own `--backend`/`--hosts` (Epic #375's shard/merge engine, including a real
EC2 fleet for `backend: "remote"` + `hosts > 1`), and the resulting `klt sim`
report is analysed by `klt yield`'s own unmodified Phase 1 pipeline -- see
docs/cli/yield.md's 'Campaign orchestration' section. That pipeline requires
the klt_yield_native Rust extension (install it with `pip install 'klayout-
tools[yield]'`, as for `klt yield`) -- see docs/cli/yield.md#building-the-
native-extension.

positional arguments:
  spec path to a campaign spec JSON file; see docs/cli/yield.md

options:
  -h, --help show this help message and exit
  -o, --out-dir OUT_DIR directory to write the dispatched `klt sim` request, its report, and artifacts into (default: a `.klt/yield-campaign/` directory next to the spec file)
  --backend BACKEND execution backend for the campaign's `klt sim` dispatch (default: local, or the spec's own `backend` field); see docs/cli/sim.md
  --hosts HOSTS shard the campaign's corner/Monte-Carlo-sample grid across this many hosts (default: 1, or the spec's own `remote.hosts` field); see docs/cli/sim.md's 'Fleet sharding' section
  --seed SEED override the campaign's Monte Carlo seed (default: the spec's own `monte_carlo.seed`, or one derived deterministically from the spec's own content)
  --confidence CONFIDENCE two-sided confidence level for every reported interval, strictly between 0 and 1 (default: 0.95, or the spec's own 'confidence' field)
  --target-ci-halfwidth TARGET_CI_HALFWIDTH half-width, in absolute yield, the sample-size verdict is measured against (default: 0.01, or the spec's own 'target_ci_halfwidth' field)
  --min-samples MIN_SAMPLES minimum usable samples per measurement (default: 2, or the spec's own 'min_samples' field)
  --measurement NAME restrict the analysis to this measurement; repeatable, and comma-separated names are accepted
  --format {text,json} output format (default: text)
