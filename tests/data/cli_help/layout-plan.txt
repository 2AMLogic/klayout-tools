usage: klt layout-plan [-h] <subcommand> ...

Execute a validated `klt.layout_plan.request/1` document onto `klt gen` + `klt
gen-compose`, producing a generated/placed/routed GDS. Takes a request-
document path. See docs/cli/layout-plan-execute.md.

positional arguments:
  <subcommand>
    execute     execute a layout-plan request into a composed GDS
    check       verify a finished layout against its layout-plan request

options:
  -h, --help    show this help message and exit

--- klt layout-plan execute ---

usage: klt layout-plan execute [-h] [--format {text,json}] request

Run a klt.layout_plan.request/1 document: resolve per-group params from the
netlist, place, route and write the GDS. Exit 3 when placed but some nets are
unrouted or unmapped.

positional arguments:
  request               path to a klt.layout_plan.request/1 JSON file

options:
  -h, --help            show this help message and exit
  --format {text,json}  output format (default: text)

--- klt layout-plan check ---

usage: klt layout-plan check [-h] --layout LAYOUT [--cell CELL]
                             [--tolerance-um TOLERANCE_UM]
                             [--format {text,json}]
                             request

Read-only: compare a finished GDS against the plan's group presence, row
order/stacking/spacing/align and abutment gaps. Exit 3 on any violation. The
JSON output is a `kind: generic` evidence envelope `klt signoff` accepts. See
docs/cli/layout-plan-check.md.

positional arguments:
  request               path to a klt.layout_plan.request/1 JSON file

options:
  -h, --help            show this help message and exit
  --layout LAYOUT       path to the finished GDS/OASIS layout
  --cell CELL           top cell name (default: the layout's only top cell)
  --tolerance-um TOLERANCE_UM
                        compliance tolerance in um (default: 0.01)
  --format {text,json}  output format (default: text)
