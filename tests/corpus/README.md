# Test corpus

A small, checked-in corpus of open-licensed example layouts from the
sky130 and gf180mcu open PDK ecosystems, plus golden JSON fixtures for the
`klt` CLI. Used by the corpus-backed tests in `tests/test_corpus.py`.

Kept intentionally small (standard-cell-sized GDS files, tens of KB total) —
this is a public repo and the corpus is checked into git.

## Golden fixtures — `tests/corpus/golden/`

`tests/corpus/golden/<pdk>/<cell>.layers.json` holds the expected
`klt layers --format json` output (i.e. the `layers_report()` result) for
the corresponding corpus file, with the `file` field recorded as the
repo-relative path for readability.

Regenerate after adding/removing a corpus file, or after a deliberate
change to the `layers_report()` schema:

```bash
python tests/corpus/generate_golden.py
```

## Machine-generated macro-scale fixture — `tests/corpus/place_and_route/`

Unlike every corpus file above (a single hand-drawn-scale standard-cell view,
downloaded verbatim from an upstream repo), `gcd.gds.gz` is **generated by
this repo's own tools** — the first real exercise of `klt drc`/`klt
precheck`/`klt layout-metrics`/`klt lvs` against machine-generated, macro-
scale, standard-cell layout rather than hand-drawn analog GDS (issue #436,
Phase 5 of [Epic #391](https://github.com/2AMLogic/klayout-tools/issues/391);
`klt lvs` added in issue #389).

- **Design**: the GCD (greatest common divisor) worked example RTL used
  throughout Epic #391 (`examples/functional-verification/gcd.v`), the same
  netlist `klt place-and-route`'s own docs (`docs/cli/place-and-route.md`)
  and worked example (issue #425 / PR #431) use.
- **Generated by**: `klt synthesize` (real Yosys 0.67+post) →
  `klt place-and-route` (real OpenROAD `26Q3-771-g7cfb2105c9`, via the
  `openroad/orfs:latest` Docker image, `linux/amd64` emulation) against
  `sky130_fd_sc_hd`/`tt_025C_1v80`, `seed: 1`, `target_stage: "route"`,
  reaching `stage_reached: "route"` with a real DEF→GDS merge — the same
  method PR #431 used to verify Phase 4 end to end (see that PR's
  description for the full transcript). `gcd.gds` was produced at
  `.klt/place-and-route/gcd.gds` and gzip-compressed here (`gcd.gds.gz`,
  ~117 KiB vs. ~816 KiB uncompressed — `klayout.db`'s `Layout.read()` reads
  gzip-compressed GDS transparently, no test-time decompression needed).
- **PDK install**: a real `volare`-fetched `sky130A` (`open_pdks`
  `bdc9412b3e468c102d01b7cf6337be06ec6e9c9a`), resolved via `$PDK_ROOT`/
  `$PDK` exactly as `klt pdk find` documents.
- **Resulting layout**: top cell `gcd`, 69 cells total (68 standard-cell/via
  library instances + the top), 3645 instances, 31 layers, ~92×92 µm die —
  a very different shape from every other corpus file here: dense
  (thousands of instances vs. a handful), one level of real hierarchy
  (top + per-cell library references) rather than a single flat cell, and
  routing-layer usage (`met1`-`met5`, vias) alongside device layers.
- **Verified against**: `klt drc`/`klt precheck`/`klt layout-metrics` (PR
  #443) and `klt lvs` (issue #389). The LVS check is a self-consistency
  round-trip (`docs/cli/lvs.md` → "Machine-generated macro-scale fixture"):
  inline-extracting the macro's own netlist (**4355 devices**, 2961 nets,
  1571 pins) and comparing the layout against it reports `status: "match"`
  with every device matched on both sides (no silently-dropped devices at
  macro scale); a deliberately-corrupted variant (one standard-cell
  transistor's width changed) is caught as a `device.property` mismatch.
  Not fully DRC-clean — `klt drc` reports 4 genuine row-gap
  `diff.enclosing.licon.1` violations traced to `klt place-and-route`
  lacking a filler-cell insertion stage (`docs/cli/drc.md` documents this as
  an input property, not a verb defect).
- **License note**: like the sky130/gf180mcu standard-cell corpus above,
  the merged GDS embeds real `sky130_fd_sc_hd` cell-view geometry from the
  SkyWater open PDK (Apache License 2.0) — the same license as
  `tests/corpus/sky130/` above; this file's provenance is recorded here per
  the same Apache-2.0 §4 obligation. `klt`'s own generated
  synthesis/place-and-route logic that produced it remains MIT-licensed,
  same as the rest of this repo.

Regenerating requires `openroad` on `$PATH` (or the `openroad/orfs` Docker
image), `yosys`, and a real `sky130A` PDK install — none of which are CI
dependencies (matching `klt place-and-route`'s own noted CI gap) — see
[`regenerate.sh`](place_and_route/regenerate.sh) for the exact, documented
steps. This is a **deliberate, reviewed** regeneration, like
`tests/corpus/generate_golden.py` / `tests/golden_metrics/
generate_golden_metrics.py` — never hand-edit the binary fixture.

## Legalizer-spike fixtures — `tests/corpus/legalize/`

Pre-legalization ("global placement") and OpenROAD-legalized DEF checkpoint

see [`legalize/README.md`](legalize/README.md) for what they are and

## STA-spike fixtures — `tests/corpus/statime/`

Mapped structural netlists (`gcd`, `mult8`, `modexp`) and an OpenSTA oracle
snapshot backing issue #809's native-Rust gate-level static-timing spike —
see [`statime/README.md`](statime/README.md) for what they are and
`native/statime/README.md` for the go/no-go result they back (**Go**,
documented there).

## Adding a new corpus file

1. Download the file into `tests/corpus/<pdk>/`, verifying the upstream
   license permits redistribution (Apache-2.0 / similarly permissive).
2. Record its provenance in the table above (source repo, pinned commit,
   license, upstream path).
3. Run `python tests/corpus/generate_golden.py` to generate its golden
   fixture.
4. `tests/test_corpus.py` picks up new corpus files automatically (it
   globs `tests/corpus/<pdk>/*.gds` / `*.oas`).

## Related: golden-metrics fixtures

The golden fixtures here pin a `klt` verb's **full** JSON response
byte-for-byte. For a narrower, **tolerance-banded scalar-metric** regression
net (device counts, cell/instance counts, DRC violation counts, ...) — the
right bar for a metric drifting slightly without the underlying geometry
becoming byte-different — see [`tests/golden_metrics/README.md`](../golden_metrics/README.md)
(issue #248).
