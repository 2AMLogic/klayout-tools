# Design pipeline worked example: sky130 5T OTA reference buffer

A worked example for [Epic #105](https://github.com/2AMLogic/klayout-tools/issues/105)
Phase 3 (issue #130): drive one small sky130 block through every
**non-blocked** stage of the staged agent design pipeline defined in
[`docs/design/design-pipeline.md`](../../docs/design/design-pipeline.md)
(Phase 1, PR #114) using the per-stage skills under `.claude/skills/`
(Phase 2, PRs #127/#128/#129).

**Block:** a five-transistor OTA (`kb:five-transistor-ota`) used as a
unity-gain follower buffering a 1.8 V reference node onto a 1 pF
switched-capacitor sampling load. Chosen for spec fit against the KB entry,
not familiarity — see [`04-topology.json`](04-topology.json).

## Artifact chain

Each file is the contracted JSON artifact (or SPICE input) the design doc's
per-stage contract (§2) names for that stage. All proposed schema names
(`klt.pipeline.<stage>/1`) are **not shipped** — no `klt` verb emits them;
they are hand-authored stage records per the skills' own framing.

| Stage | File | Produced by |
| --- | --- | --- |
| S1 design proposal | [`01-proposal.json`](01-proposal.json) | `design-proposal-intake` skill (no `klt` verb — intentionally out of tool scope) |
| S2 system architecture & budget partition | [`02-architecture.json`](02-architecture.json) | `design-architecture-partition` skill |
| S3 block spec | [`03-blockspec.json`](03-blockspec.json) | `design-block-spec` skill |
| S4 topology selection | [`04-topology.json`](04-topology.json) | `design-topology-selection` skill, KB-assisted via the shipped `klt kb search`/`show` |
| S5 sizing | [`05-sizing.json`](05-sizing.json) | `design-sizing` skill, iterated against `klt sim` feedback (Loop A) |
| S6 schematic/netlist | [`ota_5t.spice`](ota_5t.spice), regenerated by [`generate.py`](generate.py) | `design-netlist-authoring` skill (mechanical transcription of S5's sized devices) |
| S10 simulation across corners (AC) | [`sim-ac.request.json`](sim-ac.request.json) / [`sim-ac.result.json`](sim-ac.result.json) | `klt sim` (shipped, `docs/cli/sim.md`) |
| S10 simulation across corners (operating point / supply current) | [`sim-op.request.json`](sim-op.request.json) / [`sim-op.result.json`](sim-op.result.json) | `klt sim` (shipped) |

Regenerate the netlist and request JSON with:

```sh
uv run python3 examples/design-pipeline/generate.py
uv run klt sim examples/design-pipeline/sim-ac.request.json --format json
uv run klt sim examples/design-pipeline/sim-op.request.json --format json
```

(requires a resolvable sky130A PDK — `klt pdk find --pdk sky130A` — and
`ngspice` on `PATH`). The committed `sim-*.result.json` files were captured
by running exactly these commands; their `runtime_s` and
`environment.engine_version` fields are machine-dependent and will not
reproduce byte-for-byte, but the pass/fail verdicts and measured values
should.

## S10 results (schematic-level, both corner sweeps pass 20/20)

**AC sweep** ([`sim-ac.result.json`](sim-ac.result.json)) — open-loop gain,
unity-gain frequency, and phase margin, all measured across the full 5x2x2
PVT matrix:

| Measurement | Limit | Worst case | Corner |
| --- | --- | --- | --- |
| `gain_db` | min 30 dB | 37.4998 dB (margin +7.50) | `sf/1.620V/125C` |
| `ugf` | min 5 MHz | 21.83 MHz (margin +16.83 MHz) | `ss/1.620V/125C` |
| `pm_deg` | min 60 deg | 85.7444 deg (margin +25.74) | `ss/1.980V/-40C` |

**Operating-point / transient sweep**
([`sim-op.result.json`](sim-op.result.json)) — supply current and output DC
level, across the same matrix:

| Measurement | Limit | Worst case | Corner |
| --- | --- | --- | --- |

| `vout_dc` | 0.3-1.5 V | 0.888445 V (margin +0.59 from the 0.3 V floor) | `sf/1.620V/-40C` |

## Friction encountered

**S6/S5 Loop A pass 1: a testbench-methodology failure that looked like a
sizing failure.** The first open-loop AC characterization attempt (netlist
without the DC feedback network) failed `gain_db` at 3 skewed corners
(worst 19.3 dB vs. the 30 dB target). This was not a device-sizing
deficiency: the naive testbench let the output float to a
corner-dependent DC balance point that drifted toward a rail at skewed
corners, pushing a load device into triode and collapsing measured gain —
an artifact of how open-loop gain was characterized, not of the sizing.
Fixed by adding a DC feedback network (`Lfb`/`Cfb` in
[`ota_5t.spice`](ota_5t.spice)) that holds `out = vcm` at DC while opening
the loop at AC, with no sizing change. See `05-sizing.json`'s
`loop_a_history` for the full record.

Neither the `design-netlist-authoring` (S6) nor `design-sizing` (S5) skill
mentions this technique, even though it is the standard way to
characterize open-loop gain for an amplifier intended for closed-loop
(unity-gain) operation — without it, an agent following the skills as
written would burn one or more Loop A "sizing" iterations chasing a gain
shortfall that isn't a sizing problem at all. Filed as follow-on friction:
[#142](https://github.com/2AMLogic/klayout-tools/issues/142).

No other friction was hit: S7/S8-LVS/S9/S11 behaved exactly as their skills
document (explicit stubs, correctly identified before attempting any
workaround), and #54's existing tracking already covers that gap per the
`design-extraction` skill's own "comment there rather than filing a
duplicate" guidance — a comment was left on #54 rather than opening a new
issue for the same gap.
