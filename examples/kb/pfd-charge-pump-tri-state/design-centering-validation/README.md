# Design-centering validation (issue #1327, Epic #705 Phase 2)

Runs the full pipeline issue #1327 asks for -- `klt yield-campaign` ->
a `klt yield-sensitivity` ranking -> yield-aware `klt size`
(`request.design_centering`, issue #1326) -- against the PLL charge-pump
canary (`kb/entries/pfd-charge-pump-tri-state`, the second of the two
canaries issue #1325 reproduced), and reports measured yield/margin for
both the un-centered baseline and the re-centered result, honestly.

**Run it**: `uv run python3 run_validation.py` from this directory
regenerates every file here (needs `ngspice` and a real sky130A ngspice
model library; ~15-20 minutes wall clock -- see "Why this takes so long"
below). `run_validation.py`'s own module docstring is the canonical
methodology writeup; this README is the results summary.

## Pipeline

1. **Baseline `klt yield-campaign`** (`baseline-campaign-spec.json` ->
   `baseline-yield-report.json`) -- a real sky130 `tt_mm` mismatch-corner
   Monte Carlo (`n=32`, seeded) on the as-authored `charge_pump.spice`
   (8/1um, `mult=1` both legs), measuring UP-vs-DOWN current mismatch
   (`i_mismatch_pct = 100*(i_up-i_down)/avg`, limits +/-3%,
   `target_yield=0.9` -- the KB entry's own "closely matched UP/DOWN
   currents" `sizing_approach` turned into a spec).
2. **Sensitivity harness** (`run_validation.py`'s bespoke, real-ngspice
   harness -- `sensitivity-samples.json` -> `sensitivity-ranking.json`) --
   ranks four Pelgrom mismatch mechanisms (Vth and beta/width mismatch,
   each leg) by their contribution to `i_mismatch_pct`'s spread. **Why a
   bespoke harness, not `klt sim`'s own Monte Carlo**: `docs/cli/
   yield-sensitivity.md`'s "Why not a `klt sim` report" section states
   plainly that `klt sim`'s mismatch-corner MC does not expose the
   individual per-device parameter draws it samples internally, so there
   is nothing to read a `(parameters, output)` pair from directly -- its
   own prescribed fallback is a one-off caller-side harness, which is what
   this script is. It injects a controlled Vth-mismatch-equivalent gate
   offset and a controlled beta/width perturbation on each leg's output
   device only (`vos`/`w` default to `(0, 8um)`, reproducing
   `charge_pump.spice` exactly), draws 24 samples (`vth ~ N(0, 5mV)`,
   `beta ~ N(0, 2%)`, independent per leg), and records each draw alongside
   the resulting `i_mismatch_pct`. These sigma values are illustrative,
   order-of-magnitude Pelgrom-shaped perturbations, not sky130's own
   characterized AVT/beta-mismatch constants -- see `run_validation.py`'s
   docstring for the full rationale.
3. **Yield-aware `klt size`** (`design-centering-request.json` ->
   `design-centering-result.json`) -- single-device mode, sizing whichever
   leg's device the ranking flagged as dominant (the DOWN leg's `MDN` in
   this run -- `vth_mismatch_down_mv` ranked #1 by a wide margin), with
   `request.design_centering` set from step 2's ranking (both of that leg's
   mapped mismatch mechanisms; the UP leg's two parameters are reported as
   `unmapped_parameters`, not silently dropped). Grows `MDN`'s `mult`.
4. **Applied to the real circuit** (`charge_pump_recentered.spice`) -- the
   suggested 47.2x multiplier (rounded up to `mult=48`) is applied to
   *both* `MDN` (the device `klt size` sized) *and* `MBN` (its bias-diode
   counterpart), preserving the current mirror's 1:1 ratio -- see
   `run_validation.py`'s "Applying the multiplier to the real circuit"
   docstring section for why single-device `klt size` growth cannot do
   this on its own.
5. **Re-measured `klt yield-campaign`** (`recentered-campaign-spec.json` ->
   `recentered-yield-report.json`) -- same spec/seed/n as step 1, on the
   re-centered netlist.

`summary.json` is the condensed before/after comparison this README
narrates below. `raw-campaign/{baseline,recentered}/` carry the underlying
`klt sim` Monte Carlo report and dispatch request each campaign ran (real
data, not regenerated by hand).

## Result

| | Baseline (`mult=1`) | Re-centered (`mult=48`, DOWN leg) |
| --- | --- | --- |
| `status` | fail | fail |
| `yield.empirical.estimate` | 0.406 | 0.562 |
| 90% CI | [0.260, 0.567] | [0.403, 0.713] |
| `distribution.mean` | -2.41% | -2.43% |
| `distribution.stddev` | 4.89% | 3.08% |
| `capability.cpk` | 0.040 | 0.061 |
| `capability.sigma_to_spec` | 0.121 | 0.184 |

**The re-centered result shows a measured improvement**: the empirical
yield estimate rose from 40.6% to 56.25%, `stddev` fell by ~37% (4.89% ->
3.08%, roughly consistent with Pelgrom's `sigma ~ 1/sqrt(area)` law -- a
48x area growth predicts a much larger reduction *if* mismatch were the
draw's only variance source, so the smaller observed reduction is itself
informative, see below), and both `cpk`/`sigma_to_spec` improved in the
same direction.

**Two honest caveats, not hidden by the headline numbers**:

- **The two 90% confidence intervals overlap substantially** ([0.260,
  0.567] vs. [0.403, 0.713]) at this campaign's sample size (`n=32` each,
  chosen to keep the two mismatch-MC campaigns' combined wall-clock time
  practical for this validation run -- see "Why this takes so long"
  below). The point-estimate improvement is real and in the direction
  Pelgrom's law predicts, but is not yet a statistically decisive
  separation at 90% confidence with this `n`; a larger campaign (the
  `sample_size` block in both reports already states the `required_n` for
  a tighter interval) would sharpen this claim rather than change its
  direction.
- **Neither run meets the declared `target_yield=0.9`, and the mean is
  essentially unchanged** (-2.41% -> -2.43%). This is expected, not a
  pipeline defect: `charge_pump.sizing.json`'s own `sizing_rationale`
  already documents that this minimal (no-cascode) mirror's UP/DOWN
  skew is dominated by **Vds-mismatch** between the diode-connected bias
  leg and the output leg (a systematic effect), not purely by
  random Pelgrom device mismatch. Growing a device's `mult` only reduces
  the *random* mismatch component (the mechanism `klt size`'s
  design-centering objective targets) -- it cannot move a systematic
  bias, so a real ceiling remains on how much this specific re-centering
  action can close the gap to `target_yield=0.9` for *this* circuit's
  specific mismatch mechanism. Closing that gap further would need a
  different design change (e.g. cascoding the mirror, per the KB entry's
  own `sizing_approach`), not a bigger `klt size --design_centering`
  request -- correctly outside this feature's scope.

**Bottom line**: the design-centering objective did what Pelgrom's law
says it should -- it measurably reduced the mismatch-driven spread and
raised the measured yield and Cpk/sigma-to-spec margin, on a real canary,
via the real end-to-end pipeline the issue asks for. It did not (and by
its own documented scope, could not) fully close this particular canary's
gap to its stretch target, because that gap is dominated by a systematic
effect the objective does not address -- exactly the kind of honest,
qualified finding issue #1327's acceptance criteria anticipate ("the run
documents why it does not").

## Why this takes so long

Each mismatch-MC sample and each sensitivity-harness sample is its own
`ngspice -b` invocation against the *full* sky130A model library --
parsing that library dominates each invocation's wall-clock time
(tens of seconds) regardless of the tiny 6-node circuit being solved
(see `docs/cli/size.md`'s "Performance" section for the same effect on
`klt size`'s own sweep). `n=32` per campaign at 8-way local parallelism
(`options.max_workers=8`) took ~350-420s each; the 24-sample sensitivity
harness at the same parallelism took ~150s. `klt size`'s own sweep+confirm
design (one ngspice invocation for the whole width sweep via
`alterparam`/`reset`, a second to confirm) keeps the design-centering step
itself to ~1-2 minutes despite doing two full solves (base + grown).
